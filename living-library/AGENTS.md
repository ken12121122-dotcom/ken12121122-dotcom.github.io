# Living Library｜強制功能保留與版本回歸規則

適用於 `living-library/**`、與 Living Library 有關的 `packagecanvas/**` 及相應測試。Work／Codex／其他 Agent 每次修改前必須讀取本檔，以及 repository 根目錄 `AGENTS.md`。本檔只管理 Living Library UI／投影，不變更私有 GEN2 的治理規則。

## 不可違反的產品契約

1. **舊功能不能被資料來源更換所刪除。** 新增 GEN2 自動投影是「疊加」，不是「取代」既有的公開功能書、研究入口、操作入口或書內閱讀器。不得用「沒有示範書」作測試目標而移除已可用功能。
2. **無私有授權仍須能使用公開功能。** 未連線、授權失敗、斷線及離線時，必須留有安全的公開功能書與入口。私有 GEN2 內容必須清除，不能因為保留公開書而留下私人文字、ID 或 Token。
3. **來源與身分分離。** `gen2-knowledge/main/kb/` 仍是正式 GEN2 KB、Skill、Workflow 的正本；只顯示通過既有登記／Contract／候選篩選的正式投影，沿用真實 `kb_id`／`skill_id`／`workflow_id`。公開工作頁與候選研究卡是「功能／參考卡」，絕不可冒充正式 GEN2 Skill。每個實際入口有一個穩定 ID，可被多書引用而不複製身份。
4. **書本身分合併，不出現平行複本。** 《創業之書》可同時承載「公司設立任務」「創業技術研究卡」以及授權後的 `KB-STARTUP` Skill／Workflow。公開書本與正式 KB 投影映射至同一個閱讀容器；保留所有功能，但不得宣稱未經審核的內容已正式化。
5. **保留遊戲化操作閉環。** 3D 世界 → 選書／召喚 → 魔法圖鑑 → 卡片 → 書框內可上下捲動的功能 UI／MD → 返回圖鑑／關閉書本；沒有 WebGL 的裝置也須有 2D 可用入口。不得在一般同站工作頁無故整頁導航；禁止 iframe 的第三方網站須提供清楚外開備援。
6. **七個已存在的公開功能是回歸基線。** `public-capabilities.json` 列明精確身分、URL 與主要歸屬；至少其中四個 `requiredWithoutGen2` 無 GEN2 授權必須可達。研究導航、PackageCanvas、公司設立任務、Google 日曆、知識世界、GBA、Pocket Vault 均不得默默遺失。先前 12 本公用／示範書的視覺殼若有變動，須列出每本在新版本的入口或去向，且不能把展示書冒充正式 GEN2 KB。
7. **禁止重複實作後端。** 重用 `packagecanvas/gen2-source.js`，不另建正式卡片庫、不把私有 MD 放公開 repo、不額外放寬 Android Bridge。GitHub 負責儲存和 PR 審核，ChatGPT／Work／現有 Agent 依授權讀取、執行；網站不自行代替 OWNER 核准。
8. **現有可用能力以實測證據為準。** 新增功能不代表原功能可以移除。修改時先列舊／新功能對照，缺失標 FAIL，先修復再請 OWNER 驗收；不能只靠 Markdown 說明或 parser 測試宣告成功。
9. **環繞與書架必須是 3D 真實位置。** 不設死板七本上限；環繞書隨數量分多圈、不同高度。按「歸還書架」時移動同一本互動書模型至指定架位並可再次點擊召喚，不能只隱藏模型或把書轉移至底部 DOM 清單。保留不支援 WebGL 的 2D 書籍操作入口；偏好減少動態效果時，立即落位而不播放飛行動畫。書本 ID 和卡片來源不因搬動改變。
10. **空格必須真空、視角必須自由。** 未入庫的 3D 格子必須顯示清楚的空間，不得用裝飾書脊偽裝已收錄知識；「175 格」是可容納數量，不是已存在的書本數量。書架可以只配置在前方扇形，不要求背面虛構書架。手機及桌面可以自由水平 360° 旋轉、上下俯仰與縮放；任何近看、展示或書架模式不得鎖定相機視角或禁止自由拖曳。UI 必須分別標明實際書本總數、環繞數、已歸架數及總容量。

11. **封面書名優先，不做額外漂浮文字框。** 浮動書只能在原有 3D 書本封面上印放大、高對比且能自動換行的書名；不得在書本上方增加獨立文字框、告示牌、Sprite 或固定螢幕標籤。真正歸架後，書本側面（書脊）朝向走道，保留能辨識的直排書名。封面與書脊共用同一 `b.name`／正式 KB 名稱，授權重新讀取並更新時同時刷新，禁止複製硬編碼書名或以投影取代已有功能。空書格與自由 360° 視角保持原狀；有更高效能成本的畫面元素需先手機測試。

12. **人物探索必須是可退出的增量模式。** 原有中央圖書管理員可以在 3D 內實際移動，手機左側搖桿負責人物方向、右側觸控維持自由 360° 相機；桌面可用 WASD。探索模式必須由使用者主動開啟，能隨時返回原有自由觀看，不得鎖定鏡頭、變更 GEN2 資料、刪除召喚書本或書架功能。人物位置受到真實行走邊界限制，避免穿越書架；開書、搜尋、授權對話框或切至背景時立即停止行走，且不要求 GPS、裝置新權限、持續同步、Android 原生改動。若 WebGL 不可用，隱藏 3D 搖桿、保留既有 2D 書單。不得無證據宣稱已完成手機實機驗收。
13. **探索相機必須真正跟隨人物。** 移動時相機世界座標 X/Z 必須在保留相對距離與角度下同步平移，不能只更改 `camera.lookAt` 的目標、讓相機永遠繞原點。探索模式人物需要清楚可見且能調整距離；右側自由轉向、雙指縮放與退出後的圖書館中心全景一律保留。新增或修改鏡頭前需用不同 yaw 與平移座標的實際數值斷言回歸，而不是僅檢查函數名稱。

14. **漂浮書群跟隨人物，地面法陣固定。** `active`／`orbit` 書本的環繞世界中心必須依角色當下 X/Z 位置平移；書本仍保留原本多圈旋轉、點書、召喚和歸還動畫。物理書櫃及其未啟用書、地面原點法陣與環形定位光環固定在世界座標，不可掛到人物群組上一起移動。書移到書架後應停止追隨人物，從書架再召喚時回到人物周圍。維持第三人稱相機跟隨與自由觀看；不得更動 GEN2 權限。發布前至少做移動座標及書架不動的回歸測試。


## 念動世界創作資料與 Git 分支管理（2026-10-17 增補）

- 依根目錄 `AGENTS.md` 及 [`NW-BRANCH-LIFECYCLE-001`](../docs/governance/NW-BRANCH-LIFECYCLE-001_分支生命週期與分級創作發布_v1.0.md) 分類 C0～C3；**不要把 UI 定位／確認深度的 L0～L3 當成發版權限**。
- **玩家現有空白卡資料**：若僅透過已驗證的創卡術修改本機卡面／內容而不改任何程式，屬 C0，不需 Git 分支；仍遵守唯一 ID、禁任意執行權限、資料驗證與本機存檔限制。
- **《遊戲之書》新增公開設計卡**：如果需改 `living-library/live/public-catalog.js`、`index.html` 的 reader 白名單、公開 HTML／JS 或測試，屬 C1；**在目前架構仍以候選分支／PR 發布**，不因卡片是「純內容」就跳過程式回歸。
- 需要修改 3D、動畫、符文、物件身分、AI 工作流執行器時提高為 C2；涉及 Android／權限／正式 GEN2 正本則為 C3，保留既有 OWNER／CI／實機 Gate。
- 修改前優先定位同一 `book_id`、`card_id`、`surface_path` 的開放 PR；**同一項尚未完成工作必須延續其短期分支**，不可每次調整新開一條。2026-10-20 v1.1 **只對新建立的分支加嚴**：每條新分支須提供 PR 任務／查重／風險／測試／回退／結案欄位；合併與驗證後應完成安全的短期分支清理，工具不足則報 `CLEANUP_BLOCKED`。歷史快照中的 **261 條既有分支**完全不整理、不刪除、不關閉；仍不得繞過既有正式發布閘門。

## 每次變更的固定驗收

- 開發前：讀取前一個已驗證版本與當前分支，核對 `public-capabilities.json` 和來源連結；列出 **保留／新增／刪改**。
- 自動測試：必須包含 **漂浮書跟人走、空書格／地面法陣固定、歸架後不追人**、**人物探索自選模式／搖桿與 WASD、相機相對方向、真實邊界、開書暫停、關閉探索回到自由觀看、無 WebGL 隱藏搖桿**、**不出現浮動文字框、封面放大高對比字、書脊書名同源、自動更名更新、實體書本可點擊**、**多圈環繞、3D 書架實體落位／可點擊召喚、減少動態效果時立即落位**、**未授權公開入口**、**已授權 GEN2 疊加**、**斷線清除私有而保留公開**、**創業之書三類卡同時存在**、**同站書內捲動和返回**、**同功能跨書不重複身份**。
- 驗收：每個基線入口可以實際點到，不只測試 HTML 中出現 URL；手機／WebView／網頁授權不能實測就標 `NOT TESTED`。
- 若保留功能的測試失敗、被刪除或尚未實測，維持 **Draft PR / 未完成**，不得合併 `main`、不得宣稱新版已全面取代舊版。
- 新進 Agent 不得因測試名稱、過時草案、重命名「示範書」就抹掉正式可用入口。**優先處理可用功能回歸，後做 UI 美化及新投影。**


## 圖書館管理員｜UI 名詞與書籍定位規則（OWNER 2026-10-14 核准流程）

- **入口索引**：修改前必須讀取 `living-library/UI-MANAGER-REGISTRY.md`，以及當下 `main` 的 `living-library/live/public-catalog.js`、`living-library/live/index.html`。規則檔是定位程序，**不是即時資料庫快照**。不得只相信聊天記憶或前次盤點。
- **首頁語義**：沒有其他限定詞時，「圖書館首頁」＝ `/living-library/live/index.html` 的 3D 主畫面；「APP 原生首頁」＝ Android 原生控制中心。首頁／書頁／卡冊／卡片／閱讀器各有獨立 UI selector。
- **穩定識別**：書和卡片的唯一定位以 `book_id + card_id` 為主；卡槽順序 `slot_index`、展示編號 `number`、顯示名稱 `title` 是輔助資訊，不能取代 ID。
- **一次一個變更範圍**：預設 L1（定位、依賴與共享影響）；純查詢 L0；會影響行為與閱讀返回 L2；Android 原生、安全或正式 GEN2 投影 L3。修改前說明範圍，無關部分不得擅自重整。
- **書籍職責與共享**：14 本公開書的主責分類參考 `/living-library/ui-map.html`，同一張公開卡片可被多本書引用，但仍只保留一個 canonical Card ID。修改共享卡片先計算所有引用位置，不得因「重疊」就刪卡或改動既有入口。正式 GEN2 Skill/Workflow 仍由私有 `gen2-knowledge/main/kb/` 授權治理。
- **實際發布與驗收**：只有 PR/code、CI PASS、Pages HTTP、WebView 畫面、OWNER 手機點擊驗證證據各自成立才能宣稱相應狀態。缺少實機驗收不等於已在 Bridge 107 上確認可用；不得跳過上文發布閘門。

## NW-CARD-OBS-001｜每張實體卡必須可檢查完整關聯（OWNER 2026-10-20）

**固定架構規則，所有後續遊戲程式開發都必須遵守；不涉及新增 Git 分支或另一份玩家卡片資料庫。** 規格原文保存於 ChatGPT Library `/念動世界_GAME_DESIGN_KB/10_SYSTEMS/NW_CARD_OBSERVABILITY_DEPENDENCY_RULE_v1.0.md`，此文件是公開遊戲工程端的防回歸入口。

- 玩家能直接在目前實際存在的每張卡上開啟唯讀「資訊總覽」，核對卡片 ID、版本、位置、欄位、有值欄位、資料大小、圖片有無、契約、實際持有者、群組成員、法術、動畫、動作及觸發條件；需顯示明細，不可只報一個總數。
- 法術、動畫、動作要以可追溯的**穩定規則 ID／卡片 ID／目標 ID** 登記並支援反向關聯；`已設定`、`可執行`、`播放中`、`未驗證` 必須明確區分，不可從名稱或 JSON 欄位名稱直接推定能力可用。
- 執行卡片解除契約、刪除、消耗、回收或重大修改前，應能計算並向玩家解釋**實際影響哪些物件、契約與關聯**；不可逆的解除必須先展示目標、群組及術卡消耗，玩家按 ✓ 後才提交；取消不寫入。
- `living-library/live/object-craft.js` 的 `inspectCard(storage,id)` 與世界卡片 `ⓘ`、卡片編輯頁 `ⓘ` 是**第一版唯讀盤點**，只涵蓋明確辨識的既有條件式規則；目前沒有全域 runtime registry、完整反向依賴圖與即時動畫追蹤，**禁止宣稱「所有法術／動畫都已盤點完畢」**。
- 未來加入任何法術／動畫／動作／契約，必須同步提供可查詢的註冊資訊及自動驗收（純空白卡、契約群組、照片、永久卡、耗用術卡、解除前後）；只改動畫、不更新關聯索引視為未完成。
- 唯讀盤點不能改寫 `localStorage`、建立假卡、顯示已消耗的歷史術卡或洩露私人資訊。GBA 永久法術配方≠仍存在的玩家實體卡；個人圖片、真正的契約與玩家存檔需完整保護。
- **來源與驗收分離**：寫入 GitHub `main` 的工程規程≠ GBA/Pages 已部署≠手機已驗收。新設計規則不改玩家存檔；高風險程式修正仍遵守正式測試與回退 Gate。
