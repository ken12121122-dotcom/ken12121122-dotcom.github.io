念動世界
AI 創作沙盒架構AI Creation Sandbox × Card Ability Engine × Multi-Agent Control

概念草案 v0.1 · 尚未正式實作

由 AI 協助創造 3D 物件與基礎能力，玩家透過卡片自由組合、設計動畫與工作流，再讓經授權的 AI 分身在同一套規則下執行任務。

開發者建立世界規則；玩家決定創造什麼；AI 協助生成與執行。
所有真實能力都必須由執行引擎驗證，而不是只靠卡面文字或 AI 承諾。

01 / 遊戲定位與核心循環

🎮 自由創造沙盒

玩家探索、建造、嘗試並改寫自己的玩法，不必由開發者預設所有關卡。

🃏 卡片式視覺化開發

物件、動作、事件、聲音及工作流成為可組合的能力元件。

🤖 AI 協作創造

大模型產生候選物件、配置與流程；玩家可自行編輯、核准與驗證。

🌍 狀態可觀測的世界

3D 演出呈現真實任務狀態，世界不因動畫播放就假設工作完成。

玩家循環：探索 → AI 生成候選 → 玩家選擇 → 組合卡片 → 沙盒測試 → 驗證保存 → 發現新玩法。

AI 協作循環：接收任務 → 讀取已授權卡片 → 規劃 → 規則引擎檢查 → 真實執行 → 保存證據 → 世界同步。

02 / 世界創造與物件身分

AI 可以先專注建立 3D 世界。每個新物件都自動列入「3D 物件盤點清單」，但不自動卡片化。是否將物件轉為卡片，由玩家決定。

玩家描述需求 → AI 生成 3D 物件 → 登錄唯一 Object ID ↓ 玩家檢視／修改模型 → 選擇保留原物件或卡片化 ↓ 需要時建立物件卡 → 以 Card ID 引用既有物件

盤點資料包含：Object ID、名稱、模型來源、世界座標、版本、是否已卡片化、對應 Card ID、引用的能力卡與建立狀態。外觀更換、書本引用、世界投影不應產生第二個物件正本。

03 / 八類候選卡片

卡片唯一主要責任示例
📦 物件卡代表選擇卡片化的世界物件寶箱、魔法門、狐狸
🎬 動作卡可參數化的動作與視覺效果移動、旋轉、縮放、發光
✨ 符文卡事件、狀態、條件、邏輯與計時玩家靠近、AND、計時
🔊 音效卡音源引用與播放參數開門聲、施法聲、環境音
🎞️ 動畫編排卡時間軸上協調動作、聲音與事件節點卡片召喚演出
📜 法術卡把規則與效果包裝成可施放能力自動開門術、召喚術
⚙️ 工作流卡任務步驟、分支、等待與錯誤處理完成後歸檔、待核准流程
🤖 AI 分身卡角色、模型、知識來源、授權工具與配額研究分身、開發分身

設計約束：動作與音效保持獨立；多張法術卡或工作流引用同一個 canonical Card ID，不複製卡片身分；卡片名稱或類型文字本身不授予執行權限。

與早期符文書的關係：原始《遊戲之書》曾將「事件、條件、動作」一起歸入符文卡。本次候選架構提出把動作獨立為動作卡，符文卡專職事件及邏輯；此變更尚待正式定案。現有的地面初始法陣與卡片契約不是這裡的通用符文卡，兩者仍保留各自身分。

04 / 遊戲內創作編輯器

🧱 3D 物件編輯器

選取、移動、旋轉、縮放、調整相容能力，並支援產生新動作卡。

🎞️ 動畫時間軸

拖放動作卡及音效卡、多軌疊加、時間伸縮、事件節點與即時預覽。

🔊 音效素材管理

合法素材匯入、音量、播放區間、淡入淡出、循環；音檔不直接塞進卡片 JSON。

🔀 視覺化工作流

以事件、條件、法術和結果節點，組合受控操作與失敗分支。
【卡片召喚動畫編排卡】 時間軸： 0 秒 1 秒 2 秒 3 秒 動作軌： 煙霧聚集 → 卡片浮現 → 卡片飛行 → 定位 音效軌： 啟動音 → 能量音 → 飛行音 → 完成音 事件軌： start appear arrival done

播放完成不等於執行成功。動畫結束事件可觸發下一步，但正式物件狀態仍以能力引擎提交及驗證結果為準。

05 / 共同能力契約與執行引擎

所有角色都透過共同的能力介面操作世界。動作卡描述「做什麼」，而不是為每種物件另外寫一套程式。

玩家操作 / AI 分身規劃 / 工作流事件 ↓ 卡片 ID + 目標 Object ID + 參數 ↓ 能力註冊表 → 型別／狀態／權限檢查 ↓ 隔離執行 / 外部工具 ↓ 成功／失敗／待核准 + 證據 ↓ 世界狀態更新

例如「移動卡」只需檢查物件具備可移動能力、起終點合法及速度限制；不應因物件是書、箱子或椅子而產生不同的一整套移動引擎。

共同規則：驗證身分、驗證參數、限制資源與權限、防止無限循環、保存操作紀錄，並提供可安全撤銷或回退的策略。

06 / 三種世界模式與安全

🛠 創作模式

修改候選物件、卡片、動畫與工作流；不直接覆蓋正式資料。

▶ 測試模式

在隔離存檔或狀態快照中試跑，觀察結果，支援撤銷。

🌍 正式模式

執行經核准版本；權限、存檔與重要世界物件受到保護。

🔒 核准與回退

高風險操作、發布、刪除與外部工具寫入需獨立核准。

三個模式可以共用 3D 場景，但不能共用無隔離的可寫狀態。特別保留既有萬物圖鑑唯一性、永久編號及地面法陣契約，不得以普通工作流繞過。

07 / AI 分身與即時監控中心

大語言模型可以是世界中的一位 AI 分身，不只是聊天 NPC。它能在授權範圍內規劃使用卡片，執行真實任務並回報證據。

真實狀態3D 監控呈現驗證依據
待命分身停留在工作區任務佇列狀態
正在執行工作動畫／提示音執行器心跳及步驟紀錄
等待核准舉起待審卡、播放提醒受控核准紀錄
成功成果卡收錄到指定書工具回報、測試或產物證據
失敗／暫停異常提示與錯誤卡錯誤碼、超時及重試狀態

可靠性原則：大模型負責提出計畫，不自行決定是否越權；卡片規則必須由執行引擎強制驗證。動畫與 AI 自述不是完成證據。跨裝置近即時更新，需要外部事件來源、狀態存放及持續運作的服務，並非純 3D 網頁可保證。

08 / 卡片之書、法術書、手勢書的分工

容器設計中的職責
《卡片之書》實體原卡收藏、歸類、引用索引及版本管理；繼續保留現有卡槽規則。
《符文書》管理事件、條件與邏輯符文卡。
《法術書》管理與組裝受控可施放能力。
《手勢書》把玩家手勢、目標情境與已註冊動作或法術連接。
《遊戲之書》提供創作功能入口、原始設計與新架構的候選記錄。

保留原《遊戲之書》的「知識城堡｜遊戲設計」卡，將本卡作為獨立的新版本設計，不覆蓋歷史提案。

10 / 五條不可遺失的設計原則

  1. 一物一身分：物件、原卡及永久身份不因引用與投影被複製。
  2. 能力彼此獨立：動作、音效、規則與工作流各自管理。
  3. 組合優先：利用通用元件創作，降低重複開發。
  4. 玩家與 AI 共用執行規則：權限由引擎驗證，而非提示詞約束。
  5. 真實狀態優先於動畫：工作是否完成必須看可驗證證據。

待決議：八種類型是否全部為正式卡型；符文與動作邊界；法術與工作流分工；素材儲存方式；AI 分身權限、成本和背景執行；沙盒存檔隔離及分享規則。
