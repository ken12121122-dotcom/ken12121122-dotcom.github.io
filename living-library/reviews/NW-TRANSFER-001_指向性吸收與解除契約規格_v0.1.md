# NW-TRANSFER-001｜指向性轉移與具現化核心 v0.1（候選，不是已核准正式規則）

> 範圍：念動圖書館 3D 場景中的**來源物件 → 目標物件**轉移；本版重用於「解除綁定術」實驗，保留地面法陣既有締結流程，不修改 GEN2、GBA、Android。

## 1. 使用者敘述的區別
- 初始法陣：世界原點的**地面 3D 法陣**（`local.rune.origin`），不會移動。
- 初代法陣卡：使用者製作的**原始卡片**（真實 `local.card.*` ID）。解除綁定卡的最終目的地是**這張卡片表面**，不是地面法陣。
- 解除綁定術卡：使用者自行製作的另一張普通卡；施放後進入**收納／已消耗**狀態，不能當成刪除或回收。

## 2. 統一介面與階段

```
卡片/物件來源 ID (sourceId)
      │
      ├── 3 秒持續長按／完整圓形光環
      │
      ├── 候選搜尋（身份 + 有效狀態 + 3D 距離）
      │
      ├── Source world position + Target world position
      │       └── 能量連線／游動粒子／目標光環
      │
      ├── 明確確認（取消 = 0 次資料寫入）
      │
      ├── DirectedTransfer.sample (飛行 + 弧線 + 縮小)
      │       ├── world target = card front
      │       ├── world target = rune surface
      │       └── world target = book/building anchor (未開放)
      │
      └── 只有 animation.done 才進行原子狀態交易
              ├── 解除契約（目標原卡）
              └── 消耗術卡， containment.holderId=目標原卡 ID
```

- 遊戲中的飛行**不可依賴固定鏡頭座標、卡名或地面原點**；逐幀取得目標世界座標。模型的當前 ID 永不替換成展示編號。
- `directed-transfer.js` 的 `normalize()/sample()` 是獨立於 Three.js 的純數學模組。動畫與資料寫入分開，不作自動網路呼叫，也不帶權限。
- `object-craft.js` 的 `unbindAndAbsorbSpell` 在**同一 localStorage JSON 寫入**中完成「解除目標契約 + 術卡收納」。它先檢查雙方 ID/ revision / 狀態和唯一法陣關係。
- 施法途中退出、跳轉、觸控取消或失去來源時**不應改動資料**。在真正收到新的同步資料前，不顯示「已消耗」為永久狀態。
- `containment: {kind:'consumed_spell',holderId:'local.card.*',holderType:'card',state:'stored',absorbedAt:'...'}` 明確記錄收納位置，不使用 `recycled` 或刪除。
- 已消耗術卡從漂浮卡群隱藏、不能放進卡冊、編輯或一般回收；真正的再次召喚必須使用**未來另行核准的召喚術**，取回同一 `id`，不得無條件重生新卡。

## 3. 本次實作範圍（Draft PR #258）
- 玩家已有名字符合明確白名單的「解除綁定」術卡才可施法；玩家不用新建第二張測試卡，不自行改照片或卡號。
- 與地面法陣相同的持續 **3 秒 / 192 段幾何畫圓進度**，可移動角度、動畫取消規則相同。
- 距離搜尋目前限制為術卡附近 3.6 世界單位、只選 `bound` 或 `cardified` 且仍漂浮的**唯一**初始法陣契約卡，且兩個太近時拒絕猜測。
- 明確顯示聯繫，詢問是否解除。確認後定向飛行入**目標卡片**，成功後原卡解除契約並繼續漂浮；術卡進入收納。
- 不新增另一個萬物圖鑑、實體卡 ID、永久編號、GBA 送審功能。

## 4. 新增 RUNE-04 與 RUNE-05 同源卡片閉環（仍為 Draft PR #258）

1. **RUNE-04 直接吸入**：首次長按地面初始法陣 3 秒，選中鄰近普通原卡，確認後使用 `DirectedTransfer.sample` 將**原卡模型**縮小並飛入地面法陣。動畫未結束不寫入；完成後 `sealRuneCard` 單次寫入 `runeBinding.state='sealed'`、`placement='contained'`、`containment.holderId='local.rune.origin'`，原卡 ID、圖片、書面資訊不變。
2. **既有舊版 bound 卡補封印**：在同一裝置已先用舊版連結、尚未吸收的原卡，可以再次長按地面法陣，確認後**補完封印動畫**；若原卡在右側 GBA，須先取出，避免誤移。
3. **RUNE-05 第二次長按**：當原卡已 `sealed` 且隱藏於地面法陣，再次長按 3 秒，顯示「是否將初始法陣變成卡片」。確認後，同一原卡逆向飛出，`materializeRuneCard` 將其改為 `placement='hover'` / `runeBinding.state='cardified'`，**不造新 ID**；地面法陣從場景收起，之後能操作該卡及放入萬物圖鑑右側 GBA。
4. **解除綁定術後續**：3 秒長按「解除綁定」術卡，對 `cardified` 目標進行能量連線並徵求同意，術卡飛入這張實體卡。僅在動畫完成時一次寫入 `unbindAndAbsorbSpell`，原卡解除綁定，術卡 `placement='contained'`、`containment.holderId=targetCardId`，地面法陣重新顯現且可再契約。
5. **取消／中斷**：若取消對話框、失去頁面可見性、版本改變、儲存失敗，沒有原卡刪除或消耗；已經寫入的舊 `bound` 狀態仍可經原來還原頁復原，封印和卡片化狀態則不可任意重置。

## 5. 仍未實現、不可誤報通過

- **消耗術卡的重新召喚**：保存了原卡及 `holderId` 但尚無通用 `release` 交易、施法入口、權限與視覺逆向召喚。
- **L2 升級**：萬物圖鑑右側 GBA 讀卡格保留，但放入 `cardified` 不等於核准 L2，沒有永久編號、Github 正式升級的隱性自動執行。
- **任意類型目標**：轉移核心可以採用目標的世界座標，但非所有書本與建築物都已支援交互感測或存檔容器。
- **真實手機 WebGL／完整操作鏈**：Node 和 CI 瀏覽器導航測試並非 OWNER 裝置的 3D GPU 閉環；實機驗收前維持 Draft PR，不改正式 `main` 和正式版本戳。

## 6. 後續驗收建議

- 空白普通卡 → 3 秒長按地面法陣 → 確認 → **卡沒入地面法陣** → 重啟依然藏在地面法陣（ID 不變）。
- 再次長按同一法陣 3 秒 → 確認 → **原卡飛出** → 地面法陣隱藏。
- 將「解除綁定術」卡靠近具現化原卡 → 長按 3 秒 → 取消時兩卡完全不變；確認後術卡**沒入原卡卡面（非地面法陣）** → 重啟後術卡不再漂浮，但原始資料仍存，原卡變普通卡。
- 再次締約與 GBA 右側讀卡格；核對最終沒有任何新卡 ID、圖片丟失、法陣連結重複或未知產生的 L2。
