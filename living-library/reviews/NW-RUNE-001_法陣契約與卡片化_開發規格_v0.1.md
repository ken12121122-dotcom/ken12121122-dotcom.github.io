## 1. 使用者流程：兩次長按，各自不同意義

### 1.1 首次長按：選取 → 自動尋找最近卡 → 印記 → 詢問契約

1. 使用者直接按住**可見的世界法陣網格**滿 **3000ms**。開始按住即出現環形進度；完成時，外圈亮起、符文聚焦、短暫脈衝。
2. 系統按**法陣固定世界座標**與所有合法**未放入書本、在場景可見的普通卡**之實際世界座標計算距離，而不是螢幕像素距離，也不是以玩家所在地作為法陣座標。
3. 選取距離最近且唯一的卡；卡片表面顯示一枚有來源的法陣印記，外圈出現細線連結。綁定資料以原卡 `local.card.*` ID 與法陣內部 ID 對應，**不生成第二張卡**。
4. 出現操作確認：「是否施放『法陣契約術』？法陣：{法陣名稱}／媒介：{卡片名稱}」。使用者未按確認以前，**不能開始吸卡、不能變更世界／卡片形態**。
5. 取消確認 → 保留已綁定＋印記，暫不封印；日後再次長按時可以重啟同一契約確認，**不重新綁其他卡**。要換卡必須走另外明確的解除綁定程序（此版不做）。

### 1.2 契約儀式：一張原卡被法陣吸收

6. 使用者確認後，寫入 `sealing` 過渡狀態／操作 token（不重複觸發），動畫啟動。
7. 法陣外圈展開與內圈反轉 → 卡片印記呼應 → 卡片沿弧線飛往法陣核心 → 縮小、融入光點 → 卡片 mesh 消失。沿用現有煙霧/召喚相容風格，減少材質與 GPU 成本。
8. 動畫成功結束後，資料進入 `sealed`。**原卡 ID 與所有圖片、名稱、連結、revision 都保留**；卡片變成法陣內的契約媒介，不再出現在普通漂浮軌道，也不在卡片簿多占一格。法陣仍留在世界原始錨點，顯示細緻的「封印完成」狀態。

### 1.3 第二次長按：封印法陣 → 卡片形態

9. 對已封印的**同一個法陣**長按 **3000ms**，不再搜尋最近卡片，不再綁新卡。
10. 顯示：「是否要將『{法陣名稱}』變成卡片？」名稱取**法陣 entity 正式顯示名稱**；不能硬寫死成「初始」或「初代」。
11. 使用者確認後，進入 `materializing` 過渡狀態。法陣符文收束成封印、核心能量壓縮為卡面輪廓，**同一張先前被吸收的卡**從法陣中心復現，展示法陣名稱與原卡契約關係。
12. 結束後狀態 `cardified`，法陣**互動實體**在世界中隱藏且不可碰撞／不可再長按；卡片恢復可見並漂浮，可帶「契約卡」外觀。世界原點的**純定位標記**是否永久保留需 OWNER 審核（若留，只能是不可互動的地面標記，非第二份世界實體）。
13. 此時是「完成卡片化的契約卡」，**不是自動 L2、不是正式圖鑑永久收藏、不是取得編號**。未來再由 GBA 審核與 OWNER 核准提升 L2，L2 優質 3D 模型才正式套用。

### 1.4 反向兌換：卡片 → 法陣（設計候選，暫不開啟）

- 使用者希望卡片與法陣「互相兌換」；反向顯化必須設計，但**此次首版只完成法陣→卡片單向閉環的規格與計畫**，不假稱逆轉已核准。
- 反向候選操作：卡片中確認「於原錨點復現{法陣名稱}」→ 核驗場景、版本、該位置可用 → 過渡態 `restoring` → **原卡暫時消失後**同一法陣在原世界座標重新出現。
- 若失去可信原始錨點、跨設備資料衝突或世界不可載入，**拒絕反向復現，不得在玩家旁憑空生成法陣**。顯示原因與修復操作。

## 2. 狀態機與命令

| 狀態（世界/契約） | 事件與前置條件 | 下一狀態 | 代表的可見物 |
| --- | --- | --- | --- |
| `idle` | 長按滿 3 秒、存在唯一最近合法卡 | `bound` | 法陣＋帶印記的**同一張**普通卡 |
| `idle` | 找不到卡、卡已綁定或候選並列 | `idle` | 不更改卡與法陣，顯示拒絕原因 |
| `bound` | 使用者否決/關閉儀式視窗 | `bound` | 法陣＋印記卡，不吸收 |
| `bound` | 使用者確認、檢查 revision / lock | `sealing` | 暫停其他觸控操作，僅動畫投影 |
| `sealing` | 儀式完成，持久化提交成功 | `sealed` | 法陣可見、卡片隱藏但資料保留 |
| `sealed` | 第二次長按3秒並否決 | `sealed` | 法陣可見、原卡仍封存 |
| `sealed` | 第二次長按3秒並確認 | `materializing` | 轉換進行中，禁止雙份交互 |
| `materializing` | 同一 transaction 成功提交 | `cardified` | 契約卡可見、法陣實體不可交互 |
| `cardified` | 未來反向兌換確認、錨點驗證通過 | `restoring` | **未開放**，設計保留 |
| `restoring` | 同一 transaction 成功提交 | `sealed` | **未開放**，原法陣可見、卡片藏匿 |
| 任何轉換中 | 重複觸發/版本衝突/操作失敗 | 保留待恢復或回退前穩定態 | 不得出現兩份可交互對象 |

`selected` 是 **UI 暫態**，不是持久化業務狀態。長按到第 2.99 秒不可寫入正式契約；`l2_certified` 是**另一個正式升級審核域**，不可和 `cardified` 合併。

**最重要不變式**：

- 一份法陣來源 ↔ 最多一張媒介卡；媒介卡同時不得綁定第二個法陣。
- 法陣名稱與卡片名稱各有正本欄位，確認對話框從正本即時讀取；重新命名仍沿用原身分，不另創卡。
- `cardified` 時卡片是**同一個 `cardId`**；封印前後 cardId、圖片、連結、建立時間永遠不變。
- 同一唯一物件的**可交互世界實體數 + 可交互卡片實體數 ≤ 1**（`bound` 特例是「尚未卡片化的法陣＋獨立媒介卡」，兩者尚非同一物件投影）；`sealing/materializing` 兩者都不可交互。
- 不能使用前端 `hidden/visible` 代替持久化唯一性保證；裝置重新整理／重播動畫／重試後也必須能恢復。

## 3. 初始法陣及卡片的 Schema（候選）

```json
{
  "schema": "nw-rune-cardification-v1",
  "schemaVersion": 1,
  "runeId": "local.rune.origin",
  "displayName": "初始法陣",
  "worldAnchor": {
    "sceneKey": "living-library/live/index.html#main-scene",
    "position": [0, 0, 0],
    "rotation": [0, 0, 0, 1],
    "scale": [1, 1, 1],
    "verified": false
  },
  "cardId": "local.card.<existing-id>",
  "cardRevisionAtBind": null,
  "state": "idle",
  "bindingMark": null,
  "transaction": null,
  "revision": 1,
  "approvedL2": false,
  "permanentCollectionNumber": null,
  "review_status": "generated"
}
```

此示例的 `local.rune.origin` **只是候選內部 ID，不是永久公開收藏號**；位置 `[0,0,0]` 是法陣底座的 X/Z 世界原點**示意**（渲染網格分布有不同 Y 高度，正式模型中心需程式統一座標）；`worldAnchor.verified=false` 防止臆稱已具備可往返的可信錨點。`cardId` 必須由真實 card record 選定後填入，**上例的 `<existing-id>` 是占位字串，不能儲存為真實 ID**。

建議契約資料**與原卡物件放在同一份 `ObjectCraft` 原子寫入快照**，或者使用未來更嚴格的後端交易；不要在兩個不同 localStorage key 分別提交「卡被隱藏」與「法陣封印」，那會在中斷時產生半套資料。舊版 `version:1` 載入後應能保留未知欄位，移轉不得抹掉任何原卡。

`transaction`（候選）至少包含 `txId`, `type`, `fromState`, `toState`, `expectedCardRevision`, `expectedRuneRevision`, `startedAt`, `lastCommittedAt`, `retryCount`;每一命令必須具有 idempotency key，重複觸發不重複產生物件。

## 4. 最近卡片選取規則

- Raycast 必須準確命中**可見法陣本體的可互動網格**；人站在中心時不要由「整塊透明大面積碰撞板」攔截人物。
- 卡片候選集合：`record.objectType==='card'`、`status!=='recycled'`、`!containerId`、`group.visible`、不在拖曳/召喚/回收動畫、不在其他契約中、已有合法卡片名稱，並且不是正式 L2 鎖定卡。
- 以 `card.group.getWorldPosition()` 與法陣 anchor 的水平 X/Z 距離或完整 3D 距離計算；**首版建議採 X/Z 平面距離**，避免漂浮高度不一致誤選。
- 候選範圍 **3.0 場景單位（待 OWNER 校準）**；有 2 張幾乎等距時（候選判定差 < 0.15 場景單位），不猜選，提供取消/明確選擇；其他情況選唯一最近一張。
- 長按開始時不鎖定最近卡；**長按滿 3000ms 當下取快照**，用當下世界位置計算。長按/預覽/確認期間如卡片移動或 revision 改變，必須重新核驗，不能拿過期畫面強制綁定。
- 無候選、距離過遠或已有契約時顯示簡短、可理解的原因；不增加常駐文字按鈕。

## 5. 觸控、動畫與取消語義

**長按共通規則**：`performance.now()` 單調計時；按住 3000ms 完成；移動超過 12 CSS px、第二手指加入、pointercancel/lostpointercapture、視窗失焦/進入背景、開書或開對話框，都取消本次「長按進度」；取消前**不得**建立新契約。觸控命中法陣時，交互優先權才交由 rune controller；否則仍由既有 `atlasRuntime`、人物搖桿與鏡頭處理。不啟動全域長按監聽來攔截整個畫布。以 `prefers-reduced-motion` 提供即時完成/淡入替代效果。

動畫分鏡（秒數除 3s 長按外，**以下皆為可調候選值，非正式核准**）：

| 事件 | 時間 | Three.js 視覺 |
| --- | ---: | --- |
| 長按選取 | 0–3.0 秒 | 原法陣外圈漸亮，進度跟隨手勢，完成脈衝一次 |
| 綁定顯印 | 0–0.8 秒 | 最近卡片短暫靠近/亮起，卡角一枚印記和相同來源符文 |
| 契約啟動 | 0–0.9 秒 | 多圈角速度不同，光線建立卡與法陣的連結 |
| 卡片歸入 | 0.9–2.3 秒 | 原卡按弧形 `Bezier` 軌跡飛到法陣中心，縮為光點 |
| 契約結束 | 2.3–2.8 秒 | 原卡視覺消失，法陣留「封印」標記，提交 `sealed` |
| 第二次長按 | 0–3.0 秒 | 封印紋樣凝聚，完成時出確認視窗 |
| 法陣卡片化 | 0–2.6 秒 | 法陣收束→原卡復現→升到漂浮軌道；切換 `cardified` |

Animation controller 只接收狀態與世界位置，**不能單靠動畫完成事件寫入正式唯一身分、配號或 L2**；若頁面在過渡中關閉，重開後先檢查 transaction，不盲目重播「再生一張卡」。

## 6. 兌換規則與不可擅自假設

- 法陣的**實體卡片化**與普通卡**升級 L2**是兩個不同動作；「封印成功」≠「永久升級成功」。
- `初始法陣` 是 OWNER 此輪用詞；舊規則頁與候選卡亦曾寫 `初代法陣`。**本次不強制改卡片正式名稱**；實作須用真實資料名稱，交由 OWNER 驗收確認。
- 目前建立的漂亮 3D 收藏卡是**外觀候選**，不要在本流程冒充完成的 L2 認證；可在 `cardified` 使用**保留契約印記的普通卡**或候選外觀（清楚顯示待審）。
- 使用者尚未核准解綁、多張法陣、世界錨點碰撞策略、離線多設備唯一性、正式 L2、永久收藏號；全部**不實作為自動核准**。
- 採用單機原型仍只能保證**同一裝置/同一存檔快照**內的關聯完整；不能聲稱已達成跨裝置全域唯一。不可移動或覆寫原始私有知識檔案。

## 7. 失敗/復原矩陣

| 情況 | 必須結果 |
| --- | --- |
| 長按 2.9 秒放開、指尖移動或多指插入 | 取消選取動畫、不綁定、不寫入 |
| 沒有合法最近卡、候選等距或範圍外 | 不選取；顯示錯誤，不改卡 |
| 卡片已歸書、被回收、已綁其他法陣 | 拒絕；不搬走、不覆寫 |

| 第二次卡片化點否 | 保留已封印法陣，卡仍封存 |
| 卡片 revision/世界錨點已變 | 版本衝突，拒絕舊命令；不得篡改另一張卡 |
| 儲存空間不足或寫入失敗 | 原始快照維持、顯示可恢復狀態；不丟失圖片/記錄 |
| 動畫被關閉/重整/失焦 | 重讀交易狀態後恢復或安全回退；不出現 2 份互動物 |
| WebGL 不可用 | 保留 2D 預備方案與可讀資訊；不可因渲染失敗改變契約資料 |
| 跨裝置備份衝突/無可信錨點 | 停止任何承諾唯一性的兌換；不生成新的世界實體 |

## 8. 驗收範圍（必做但此文件未執行）

**功能驗收**：兩次獨立 3 秒長按、唯一最近卡、印記、兩次確認對話框、原卡吸入/復現、取消/重複/中斷、資料單寫入與不重複。  
**視覺驗收**：法陣固定於地面世界原點、同一張卡保留 3D 外觀與圖片、印記看得見但不遮圖、卡飛行路徑正確、手機能看清轉化、精簡 UI、不鎖定相機。  
**安全驗收**：未核准永久編號/L2、不能繞過 OWNER gate、舊卡/書/GEN2/Android 不受影響，沒有 WebGL 仍保留舊 2D 功能。  
**測試狀態**：本文件階段全部標記 `NOT IMPLEMENTED / NOT TESTED`；實作及 CI/手機驗收在 B 計畫中逐項追蹤。
