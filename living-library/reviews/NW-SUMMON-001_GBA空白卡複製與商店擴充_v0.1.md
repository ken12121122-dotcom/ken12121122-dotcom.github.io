# NW-SUMMON-001 / GBA-COPY-001｜逆向召喚架構、空白卡複製與未來商店 v0.1

狀態：**候選規格／Draft PR #258，未發布，不代表玩家裝置已驗收**。
範圍：僅念動圖書館既有卡片和萬物圖鑑的右側 GBA；不改 Android APK、GEN2、公開卡片身份，亦不提供金流。

## 1. 模型分離：原卡、複製載體、物件內收納卡

- 任何卡片的唯一身分是 `local.card.*`。視覺編號 `cardNumber`、左側卡格 `slotIndex` 和來源標題都不是唯一主鍵。
- 「原卡」的 `copyPolicy`、契約、憑證、L2、權限、GBA 送審或唯一性，不由圖像複製而轉移。
- 「空白卡」是可用的**實體媒介**，不是下載圖案、不是付費貨幣、不是新的卡片 ID 複製器。
- 「已消耗的解除綁定術卡」保存在 `placement:'contained'` 和 `containment.holderId=原卡 ID`，既不在漂浮圈，也不在回收站。重新召喚應取回該 ID，不再建立同名新卡。
- `summon-plan.js` 可以查詢某個 holderId 內存在多少真實收納卡、辨別 `rune_contract` 與 `consumed_spell`，但刻意**不執行釋放或重置能力**。未來由已核准召喚卡、目標定位、使用者確認和交易引擎共同啟用。

## 2. 本階段 GBA 複製操作

```text
使用者先將「普通來源卡」拖進萬物圖鑑左頁 1~9 格
                       │
                    來源卡不動
                       │
從漂浮卡群選取一張「完全未使用的空白卡」
                       │
放進右頁 GBA 唯一讀卡格（slotIndex=9）
                       │
GBA 進入近距離模式 → SELECT 循環到「複製卡面」
                       │
↑↓ 在左頁可複製普通卡中切換
                       │
A → 明確顯示來源卡與複製限制的確認視窗
                       │
確定 → 同一 localStorage 寫入（來源保留、空白卡內容更新）
                       │
空白媒介轉成卡面複本，保持自己的獨立卡片 ID
```

**複製內容**：名稱、說明、內容類型、自選圖片及裁切；來源卡保持原位／原狀。若來源圖片大，localStorage 空間不足會整筆失敗、不消耗空白卡。

**不可複製內容**：來源 ID、永久編號、卡格、技能／法術能力、法陣契約、已消耗狀態、所有權／特殊權限、認證狀態、GitHub URL 連結、唯一身份。複本記錄 `copyInfo:{kind:'appearance',sourceId,sourceRevision,copiedAt}` 作可追溯資訊。現階段複製只是**卡面**，不等於施法卡有效具現化或正式 GBA 認證。這避免普通複製介面繞過卡片「唯一」和安全規則。

**拒絕**：目標不是空白卡、不是右側讀卡格、原卡不在左側九格、來源屬封印／已消耗／認證／能力／唯一、任何 ID 或 revision 失配、來源不存在、儲存異常。所有拒絕都保持兩張原卡不變。

## 3. 待未來核准的召喚與商店系統

### 逆向召喚

- 召喚法術卡（仍需玩家設計）3 秒長按，搜尋附近**持有收納關係的容器**，如初代法陣卡。
- 經篩選後列出與該物件 `holderId` 相符的真實原始卡 ID。不可只靠顯示名稱匹配。
- 顯示是否取回，確認後重用 NW-TRANSFER-001 將收納卡從目標卡面飛出。
- 獨立原子資料交易：`placement:'contained' → 'hover'`，清除持有關係；**不重設 consumed_spell、契約、充能狀態或版本紀錄**。能否再次施法由另一個經核准的魔法負責。
- 另檢查容量上限、收納循環、過期/移動中的目標、同時觸控取消和競態保護。

### 商店與空白卡補充

- 未來商店可以提供「空白卡」作為商品，購買後才用既有 `createBlankCard` 鑄造新且唯一的 `local.card.*`。
- **本期不實作**購買、金額、支付、訂單、金鑰、真實庫存或任何商店授權。
- 日後商店需另外定義虛擬經濟／收費模式，並先驗證購買紀錄的冪等性與權限；不能只因客戶端 UI 顯示購買成功就增發卡片。
- 延續現行本機 `MAX_CARDS=64` 的保護，不能藉複製突破上限，也不能以複製來源身分替代真正發卡。
