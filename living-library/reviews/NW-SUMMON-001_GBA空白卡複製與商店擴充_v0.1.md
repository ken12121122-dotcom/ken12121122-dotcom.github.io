## 1. 兩個功能不可混為一談

| 功能代號 | 產品名稱 | 正確操作 | 狀態 |
| --- | --- | --- | --- |
| `GBA-FORGE-001` | **GBA 卡片格式下載／空白卡具現化** | 從 GBA 自己的懷舊系統選單，選擇過去已建立、允許複製的卡片格式；右側實體讀卡格只需放空白卡即可寫入 | v0.2 候選實作 |
| `CARD-COPY-001` | **複製卡**（另外的卡片／能力構想） | 是否需要某張複製卡、能否不經 GBA、怎樣複製、施法效果、消耗與限制 | **待討論；沒有核准玩法或正式介面** |
| `NW-SUMMON-001` | **逆向召喚** | 從持有者 ID 找回原被吸收卡片（同一原始 ID） | 只有唯讀查詢架構，不解封 |
| `SHOP-001` | **商店** | 未來購買空白卡等物件 | 預留選單入口，但不可購物 |

舊候選程式 `copySources/copyIntoBlankCard` 原本只看左九格，現在**移出 GBA 使用路徑**並註記為 `CARD-COPY-001` 實驗原型；不可將其視為「GBA 下載」正式規則。尚未決定是否保留其左九格機制。

## 2. GBA 使用者體驗

```text
GBA 螢幕（具遊戲機實體按鍵）
       │
       └── SELECT → 系統選單
                     ├── 卡片檢視
                     ├── AI 觀察（原有功能）
                     ├── 卡片下載 ← 選這項
                     └── 商店（未開放）
                               
右側 GBA 讀卡格 ← 放入一張新空白卡
       │
GBA 卡片下載 → 讀取「已建立且可下載的格式清單」
       │
       ├── 來源卡可在世界漂浮、其他書本內或已被消耗
       │   （因為讀的是系統保存的卡片格式，不是物理左側卡）
       └── 左側九格完全沒有前置需求
       │
↑↓ 選擇名稱 → A → 明確確認
       │
GBA 進度條／右側空白卡模型短暫呼吸效果
       │
完成後在原空白卡 ID 上寫入已選卡面／圖片／說明
       │
可將具現化卡拖出 GBA；原始來源卡不變
```

輸入原則：**SELECT 打開系統選單，方向鍵操作選項，A 確認，B 返回；START 保留原退回鏡頭操作。**舊的 `card/observe` 讀卡與 AI 觀察通道保留。GBA 畫面清楚顯示選單；不在世界另外新增文字按鈕。

### 下載來源清單

- 本機 ObjectCraft 卡片正本 `living-library-player-objects-v1`。候選可下載狀態為使用者已建立、`draft`、非空白且非唯一、沒有 L2／授權／契約／正式能力的普通卡面；不強迫移到左九格。
- 已消耗但保存了實體原始資料的**普通名稱型魔法**，可以被當成格式來源重新下載；這是把格式寫入**另一張新空白卡**，不等於將消耗掉的原 ID 召喚回來。
- 現階段採取限制式預設，未來可加入獨立 `templatePolicy` 管理、搜尋、版本與允許下載的審核；不自行複製受保護／唯一卡片。
- 名稱型「解除綁定術」的卡面可下載成新的獨立 ID；是否可以施法仍由既有能力契約判定，不複製正式權限。

### 資料安全

- `listDownloadableTemplates`：只讀取已建立卡片候選。
- `forgeBlankFromTemplate`：在**一筆 atomic localStorage 寫入**中將來源圖像、名稱、一般說明和卡片類型載入既有空白卡；保留空白卡原本的 `id`，不造新的來源卡 ID，不改來源卡，也不複製原編號、契約、能力、專用連結或 L2。
- 以 `copyInfo.kind='gba-template-download'` 記錄範本 ID 與來源版本。對象版本已變、重複使用空白卡或儲存失敗時整筆拒絕。
- 動畫只是呈現下載過程，**資料寫入只發生在成功完成動畫後**；按 B、失去焦點或背景中斷不改資料。

## 3. CARD-COPY-001｜複製卡待討論

使用者提出可區別於 GBA 的「複製卡」：可能是卡片魔法、世界物件直接複製、或另一種規則，但**目前沒有確認其發動方式、材料、重複次數、目標或能力限制**。

僅將舊左九格原型標記為**未核准候選**。不得因其程式已存在就直接上線，也不得宣稱必須將範本放在左頁才能下載。

## 4. 逆向召喚和商店仍獨立

- 逆向召喚是 `holderId → 原始被收納卡 ID` 的物件轉移：原卡 ID 不變；與「新空白卡下載同款卡面」不同。仍缺施法與真正取回操作。
- 商店未來可販售空白卡；目前 3D GBA 選單只顯示「商店（未開放）」，不支付、不扣款、不建立訂單，也不增加卡片容量上限。
- `CARD-COPY-001` 未核准，不與商店或召喚互相偷渡授權。

## 5. 永久編號卡登錄（延後啟用，OWNER 2026-10-17 補充）

**功能名稱：PERMANENT-CARD-REGISTRY-001｜永久編號卡。**

使用者指出 GBA 將來還需要「永久編號卡」功能，但**目前尚無可登錄的永久編號卡**；必須**等待初代法陣卡完成後續升級，再討論正式登錄**。

依賴順序固定為：

```text
初代法陣卡建立、締結、具現化
        ↓
未來的法陣卡升級機制真正完成並驗證
        ↓
確定永久編號規則及登錄資格
        ↓
才將取得資格的永久編號卡登錄到 GBA 對應名錄
```

此項現在只記錄為 GBA **未來功能需求**，**不新增可操作選單、不建立假卡、不發放號碼、不預先登錄、不自動升級**。GBA 現有卡片下載與商店預留入口不受影響。

重要區分：玩家手動填寫的 `cardNumber` 只是可編輯展示文字，不等同於已獲正式、獨一無二且不可任意更改的「永久編號」。正式登錄還需要另外確立獨立身份、編號配發與不可複製規則；不能把普通 GBA 格式下載誤作永久卡複製。法陣卡僅 `cardified` 不代表已完成升級。

登錄功能何時顯示為 GBA 選單、是否只讀展示、以及審核／升級如何觸發，均待法陣卡升級方案確認後再設計，不能先假設已經存在。

## 6. 驗收

- 已建立可下載卡在其他書本、漂浮圈或已消耗／已收納狀態，**不放入左九格**也應可列出。
- 右側放空白卡 → SELECT → 卡片下載 → ↑↓ 選格式 → A → 確認 → 進度條 → 空白卡原 ID 具現化；重新載入後仍能檢視。
- 取消、版本過期、特殊能力／唯一卡、讀卡格沒有空白卡與 localStorage 存滿都不得複製資料。
- 既有 GBA 右槽讀卡、AI 功能、左右展示格、卡片拖曳、遊戲書、安卓與正式 GEN2 入口不能退化。
- Node 回歸、CI browser、GitHub Pages 候選和 OWNER 手機實際按鍵須**分別**驗收，不得宣稱有 CI PASS 就正式發布。
